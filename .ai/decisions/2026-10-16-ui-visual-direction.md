# 视觉方向：clip 页面采用「工作台仪表」设计系统

**Status:** ✅ ACCEPTED · **Date:** 2026-10-16 · **Deciders:** 用户（要求「整体大换皮」）· **Supersedes:** none

## Context

页面（`internal/clip/page.html` + `page.go` 的 `landingHTML`）此前是一套中性灰蓝主题
（`--accent:#1f6feb`、`--line` 细边、圆角卡片）。功能已完整（步骤 ① 密码、步骤 ② 分享），
定位是 **webnote.cc 的开源版本**，但视觉上是一套「任何 AI 都能生成的开发者工具」：
企业蓝 + 系统字体 + 圆角卡片 + 柔和阴影。用户要求「美化 UI…做个整体的大换皮」。

摆不掉的硬约束（决定了可选方案空间）：

1. **CSP 是 `default-src 'none'`**：不许 `style="…"` 内联属性、不许外链 CSS/JS、**不许 webfont**。
   字体只能来自系统栈。
2. **一个模板两种形态**（clip 编辑器 / 只读分享视图），`writable = !isShare;` 被契约测试钉住。
3. **一批 id 与中文文案被 `scripts/verify-clip-browser.cjs` 断言**（75 条），改文案必须同改动改脚本。
4. **`white-space:pre` 的 textarea 是刻意的**（换行回流 = 内容被改坏）。
5. 无障碍基线已被记录为「按钮 36px、首页 44px、focus 可见」。

真正的**设计问题**是：这个产品的主体是「一段要同时存在于两台机器上的文本」，
用的人开着终端、正在排障、没耐心。而当时的页面把它做成了一个通用的「文档编辑器 + 卡片」。

## Options

| Option | Upside | Downside | Reversibility |
| --- | --- | --- | --- |
| A 什么都不动，只调间距/圆角 | 风险最低 | 没解决「看起来像模板」，用户明确要大换皮 | 易 |
| B 交给 ui-ux-pro-max 生成的设计系统（企业蓝 #2563EB + Inter + Swiss Minimalism） | 有数据支撑、一套完整 token | 正好是它自己在 `AVOID` 里警告的通用解；**Inter 是 Google Font，CSP 下用不了**；换汤不换药 | 易 |
| C **「工作台仪表」**：仪器面板词汇（发丝缝替代阴影、实测 3:1 控件边界）、单一信号色（青绿）、琥珀只留给警告、**等宽只留给载荷与地址**、读数字用无衬线 + tabular-nums、状态灯作为唯一的「大胆之处」 | 从产品主体（终端/传输/仪表）长出来，不是模板；仍然零外部资源、零构建 | 需要自己把每个色对的对比度算清楚；两套模式都要单独设计 | 中（token 层可整体替换） |
| D 主题化：暗色 + 磷光绿/琥珀终端风 | 一眼「运维味」 | 正是 Anthropic `frontend-design` 技能点名的 AI 默认套路（近黑 + 单一酸性绿），且会把琥珀这个「警告」语义用掉 | 易 |

## Decision

采用 **C（「工作台仪表」）**。它是唯一同时满足「从主体长出来的独特性」与
「零外部资源」的选项；B 与 D 都被 `frontend-design` 技能的「反 AI 默认清单」直接命中。

落地为规则，而不是偏好：

- **配色走 `:root` 变量 + `prefers-color-scheme:dark`，两套都是独立设计的**（浅色 = 绘图纸，不是反色）。
  两组灰是**不同的 token**，不能互换：`--seam` 只做分隔线（视觉性，1.3–1.7:1 可接受）；
  `--edge` 是控件边界（**实测 ≥3:1**，WCAG 1.4.11 非文本对比）。
- **单一强调色承担「活着」的语义**（保存中/同步中/已解锁）；**琥珀只表示警告**；
  `--err` 只表示错误。颜色永不单独承载状态 —— 每个状态都有文字或形状陪跑（状态灯 + 文案）。
- **等宽字体只给载荷与地址**（textarea、`.addr`、分享链接、取件码、`code`）；
  版本号/过期时间这类**读数用无衬线 + `font-variant-numeric:tabular-nums`**。
  这条规则是可检验的：页面上出现等宽字 = 那就是正在被传输的东西。
- **控件边界用 `--edge`（3:1），结构用 `--seam` 发丝线，深度不用阴影**。
- **圆角同心**：`外圆角 = 内圆角 + padding + 边框`（`--r-ctl:8px` → `--r-panel:19px` / `--r-panel-lg:23px`）。
- **触控目标：桌面 36px（保既有密度），`@media (pointer:coarse)` 下 44px**。
  （WCAG 2.1 SC 2.5.5 是 AAA；AA 对应 2.5.8 要求 24px —— 36px 本就过 AA。粗指针下抬到 44px 是无代价的。）
- **焦点环显式声明一次**：`:where(a,button,input,textarea,summary,label.file):focus-visible`，
  `outline:2px solid var(--accent); outline-offset:2px`。offset 是承重的：
  它让主按钮上的环对着页面底色测量（5.5:1），而不是对着它自己会消失进去的强调色面。

## Consequences

- 更容易：以后调色只改 token；暗色/浅色被同一组断言的对比度检查覆盖。
- 更难：**新增颜色必须重算对比度**（`--edge` 混用成 `--seam` 会让控件边界掉到 2.x:1）。
- 必须成立：`scripts/check.sh` 绿 + 真库 `scripts/test-pg.sh` 绿 + 真浏览器 75/75 +
  **本机 DOM 实测**（106 组文本/底色对比 0 失败、Tab 顺序 11 站全部画出焦点环）。
- 视觉方向本身**没有做过人眼审查**（本会话可用模型无视觉能力）：截图留给人类过目后才提交/部署。
- 已记入 `.ai/CURRENT_TASK.md` 的「未做」：`<details class="meta">` 里的
  设置/去掉密码控件在**锁定态**下仍然渲染（点了必 401）—— 这是**既有**缺陷，
  不是本次换皮引入的；它需要动 `paint()` 的状态机，故未在本次一并修。

## Revisit when

出现下面任一条：

- 有人真的抱怨「看不清」或「分不出重点」（而不是风格偏好）；
- 需要引入 webfont（那要同时改 `PageCSP`/`landingCSP` 与「零外部资源」这条定位）；
- 页面上出现第三种「活着」的语义色（说明单一强调色已经不够用，需要拆语义）；
- 移动端成为主要入口（那时 `pointer:coarse` 的 44px 应该直接成为默认值）。
