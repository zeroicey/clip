# 给后缀加访问密码（可选）

· **Supersedes:** none

## 背景

定位改了：clip 要做 **webnote.cc 的开源版本**。webnote 把「设置访问密码」明确写成
「隐私信息传递」的手段，所以这是对标清单里的下一个缺口，不是锦上添花。

**冲突点（必须先说清）**：本仓库现在的硬约定是「**后缀是公屏，不是密码**」，README 写
「别往里放密码、密钥或任何机密」。加了密码之后这句话**只对没有密码的 clip 继续成立** ——
这条约定要改，但不能靠改文案糊过去：它必须变成「密码是一个**可选的**第二把锁，
无密码的 clip 仍然公开」。

### 影响设计的事实（都是当前代码的实际形状）

| 事实 | 后果 |
| --- | --- |
| 页面正文是**服务端渲染进 HTML 的**（`renderPage`） | 上锁的 clip **不能**把正文渲进页面，必须渲成「锁」的壳 |
| 读路径有 **4** 条：`/<后缀>`、`/<后缀>/raw`、`/<后缀>/raw/N`、`GET /api/clips/:suffix`（带 long-poll `?wait=`） | 任何一条不设防，密码就只是装饰；漏掉 `/api` 那条约等于开了后门 |
| 写路径已有 owner token（`X-Relay-Clip-Token`，库里只存 sha256） | 密码**不必**再管写；两把钥匙各管一件事 |
| 「未知后缀」与「存在但无权」现在**响应形状一致**（页面 200 空编辑器 / raw 404） | 解锁失败不能泄漏「这个后缀存在」 |
| 限流键必须走 `internal/clientip`；时间一律 epoch 毫秒 | 防爆破要复用既有件，不要新造 IP 判定 |

## 选项

### 分歧一：密码由谁校验

| 选项 | 好处 | 代价 | 可逆性 |
| --- | --- | --- | --- |
| **A. 服务端口令**（argon2id 哈希入库，服务端解密后下发正文） | 最快落地；`/raw` 照旧 `curl` 就能拿文本（这是本项目最好的那个功能）；忘了密码可以靠改密码救回（有 token 的话）；long-poll、图片、TTL 全不动 | **运营者能读内容** —— 它挡的是「猜到后缀的人」，不是「服务运营者」。对开源版本要如实说明 | easy（加一列，去掉即可） |
| **B. 端到端加密**（密码派生密钥，服务端只存密文） | 运营者也读不到；「不是全公开」的最强形式 | **`/raw` 变成密文** → 运维在另一台机器 `curl` 拿文本这个核心场景没了（除非再写并分发一个解密 CLI）；图片也要加密；long-poll 仍可用但客户端要解密；忘了密码 = 内容永久不可读；复杂度高一大截 | hard（改成 A 要重写数据） |
| **C. 先 A，把 B 记为后续**（无密码 → 明文；有密码 → 服务端口令；将来再加「端到端」档） | 不锁死方向；先用最小代价覆盖「别让人猜到就看见」 | 需要一开始就把「加密档」的位置留在数据模型里，否则将来要迁移 | medium |

**推荐 A（把 C 当作落地方式）**：理由是 `/raw`。本项目的价值主张是「Linux 运维两台机器搬文本」，
而 B 直接把这个场景打掉一半。B 值得做，但应该等真有人要「连运营者也读不到」时再做（见「何时重开」）。

### 分歧二：密码挡哪几条读路径

**已在「决定」里定下：全部 4 条**（含 `/raw`）。保留本节是因为这条当初被单独权衡过，
而“只挡页面”那个选项就是假锁。

### 分歧三：密码怎么传

- **页面**：`POST /api/clips/:suffix/unlock`，body `{"password":"…"}` → 返回 `clipData`。
  **不发新的长期密钥** —— 多一个可泄漏物没有收益；页面把密码留在内存/sessionStorage 里供轮询用。
- **curl / 运维**：`curl -H 'X-Clip-Password: …' https://…/后缀/raw`。
- **明确不用**：query string（`?password=`）—— 会进 Caddy 访问日志、浏览器历史和 Referer。
  这与 runbook 里已经记录的「Caddy 站点日志会明文记 header」是同一类风险，所以**必须同时**
  确认 Caddy 的 `log` 块过滤掉 `X-Clip-Password`（和现有的 `X-Relay-Clip-Token` 一起）。
- **明确拒绝**：密码进 URL 路径（会进日志，也会跟着分享链接一起泄漏）。

### 分歧四：存什么

- **一列 `password_hash`**，放 argon2id 的 PHC 字符串（自带 salt 与参数）—— 不要自己拼 `salt` 列，
  也不要发明格式。`NULL` = 无密码（公开），与现有数据天然兼容。
- 密码明文**永不入库、永不进日志、永不回显**（连 owner 也不回显）。
- 设/改/去掉密码都需要 owner token（与更新正文同一套所有权判定，写在 SQL 的 `WHERE` 里）。

## 必须同时做的防爆破

没有这一节，密码就是心理安慰 —— 短后缀 + 弱密码几秒就破：

1. **解锁失败限流**：按 IP（复用 `internal/ratelimit`）**并且**按后缀（新增一个小计数器）。
   只按 IP 不够：换 IP 就绕过；只按后缀不够：会被人拿来锁死别人。
2. **常量时间比较**：argon2 校验自带，不要手写 `==`。
3. **不泄漏存在性**：解锁失败与「后缀不存在」在**各自的响应形状里**保持一致
   （页面路径都走同一个壳，`/api` 路径都走同一个封套错误码）。
4. **文案要诚实**：短后缀 + 弱密码仍可被爆破；UI 上提示「用随机长后缀 + 长密码」。

## 决定

采用 **A（服务端口令）**，按用户裁决落地：

1. **存储**：库里只存 **argon2id 的 PHC 字符串**（`$argon2id$v=19$m=…$salt$hash`，自带 salt 与参数），
   `NULL` = 无密码。用户说的“加密存进去”—— 准确地说是**哈希**：单向、不能解密。
   这是对的，因为我们不需要知道密码原文，只需要能校验。明文永不入库、永不回显、永不进日志。
2. **保护范围：全部 4 条读路径**，`/raw` 也在内 —— 用户明确问了这一条（“这个接口应该也要传密码才行啊”）。
   页面、`/<后缀>/raw`、`/<后缀>/raw/N`、`GET /api/clips/:suffix`（含 long-poll）全部要先过密码。
   **任何一条不设防，密码就只是装饰。** `/raw` 不是后门，它是从第一天就写进 README 的
   「另一台机器只有 curl」入口，所以它必须跟着一起上锁。
3. **密码怎么传**：
   - 页面：`POST /api/clips/:suffix/unlock`，body `{"password":"…"}` → 返回 `clipData`；
     **不发新的长期密钥**（多一个可泄漏物没有收益）。
   - 命令行：`curl -H 'X-Clip-Password: …' https://…/<后缀>/raw`。
   - **禁止** query string 与 URL 路径（会进 Caddy 日志/浏览器历史/Referer）。
     若开 Caddy 站点日志，必须把 `X-Clip-Password` 和现有的 `X-Relay-Clip-Token` 一起过滤。
4. **忘记密码 = 不可恢复**：没有找回流程，也不给“重置”。用户的原话：
   “忘记密码就不可重试了，只能真正的丢弃”。内容只能等过期/被清掉，或者换一个后缀重来。
   （这条与下面那条写权限的裁决绑在一起：**密码就是单一把手钥匙**。）
5. **防爆破是必需项，不是加固项**（短后缀 + 弱密码几秒就破）：
   解锁失败要同时按 **IP**（复用 `internal/ratelimit`）与 **后缀** 限流；
   失败响应不能泄漏“这个后缀存不存在”（与现有「未知后缀响应形状一致」的约定保持一致）；
   UI 要诚实提示“短后缀 + 弱密码仍可被爆破”。
6. **密码的设/改/去**都要过所有权判定，写在 SQL 的 `WHERE` 里（与现有更新路径同一套写法）。
7. **过期即回收后缀**：用户要求“长时间没人请求就把链接丢弃销毁，然后重新开放这个链接”——
   这正是现有 `sweep` + `expires_at` 的行为（删行即释放后缀），不需要新机制，只需要保证它继续成立。

落地细节：迁移加一列 `password_hash`（`NULL` 兼容全部存量数据）+ `sqlc generate`；
页面从“服务端直出正文”改成“壳 → 解锁后拉取”；无密码的 clip 行为不变。

## 后果

**会变容易**：可以在两机之间传敏感内容（webnote 的「隐私信息传递」场景）；对标清单少一项。

**会变难 / 必须成立的事**：

- 「后缀是公屏」这条硬约定要**同时**改 AGENTS.md、README、页面文案、`.ai/`，否则记忆库与代码矛盾。
- 文档必须写明：A 方案下**运营者可以读内容**（这是与 B 的分界线）；忘记密码**不可找回**。
- 页面从「服务端直出正文」变成「壳 + 解锁后拉取」，多一次往返；无密码的 clip 保持原样。
- 新增迁移 + sqlc 重新生成（闸门里的 `sqlc diff` 会盯漂移）。
- 契约测试要钉住新字段（请求 camelCase / 响应 snake_case，写错是静默的）。

## 验收（完成定义，沿用仓库既有标准）

- **真库** `scripts/test-pg.sh`：哈希与校验、无密码兼容、改密码要 token、解锁限流。
- **真浏览器** `scripts/verify-clip-browser.cjs`：加密码 → 另一个浏览器只看到锁 →
  解锁可见 → 错密码不给内容 → `/raw` 不带密码不返回正文。
- `scripts/check.sh` 全绿、`sqlc diff` 无漂移。

## 顺带要决定的（不属于本提案，但一起做更省事）

- **LICENSE**：要当「开源版本」，仓库里现在**一个 license 文件都没有** —— 这是前提，不是细节。
- 与 webnote 的其余差距：只读模式、自动保存、随机后缀生成、中文后缀、文件类型范围。

## 何时重开

- 有人明确要「**运营者也读不到**」→ 上 B（端到端加密），届时数据模型要能容纳密文。
- 需要 `curl` 拿密文也能解密（例如提供 `clip decrypt` 小工具）→ B 的代价降到可接受。
