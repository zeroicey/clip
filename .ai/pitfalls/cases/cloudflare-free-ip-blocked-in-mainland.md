# Cloudflare 免费版 IP 在大陆被 TCP 层封锁（本架构改动的根因）

**Severity:** 🔴 high · **First hit:** 2026-10-09 · **Hits since:** 1

## Symptom

`https://teleport.zeroicey.me/` 在中国大陆**稳定**打不开（两个大陆观测点：广东电信家宽、
hcyj 本身）。浏览器表现为超时/连接重置，不是 4xx/5xx。而在境外（Azure 香港）
**300/300 全通**。

## Root cause

**封锁发生在 IP 层，不是域名层、不是 SNI 层。** Cloudflare 免费版为该 zone 分配的
`104.21.55.38` 与 `172.67.144.109` 这两个 anycast IPv4 在大陆被 TCP 过滤。

排查矩阵（决定性证据）：

| 检查 | 结果 |
| --- | --- |
| DNS（223.5.5.5 / 119.29.29.29 / 8.8.8.8 / 1.1.1.1） | **正常**，都返回同一对 CF IP |
| ICMP ping | **通**，233ms，0% 丢包 |
| TCP 443 / 80 / 2053 | **全部阻断**，连续 3 轮稳定 |
| 同一 SNI，换 CF 边缘 IP | `104.16.0.1`…`104.27.0.1`、`188.114.96.1` → **200** |
| 同一 SNI，另一些 CF IP | `162.159.0.1`、`108.162.192.1` → 403；`172.65.0.1` → 超时 |
| 对照：同一台服务器 `api.hcyj.xyz/.../api/health` | 大陆 **200** |

DNS 没被污染（那通常返回假 IP），ICMP 也通（不是路由黑洞）—— 这正是"TCP 层过滤"
的特征。域名、证书、Worker、后端全都是好的。

## Fix

把前端也交给国内服务器，只保留一个大陆可达的入口
（`.ai/decisions/2026-10-09-mainland-reachability-single-entry.md`）。
CF 侧全部下线。

**为什么不用「优选 IP」绕过**：CF 优选 IP 要求把 DNS 移出 Cloudflare（CNAME 接入），
而一旦 DNS 不托管在 CF，**Worker 就不再运行**，方案自毁。CF 官方大陆加速需要
企业版 + 域名 ICP 备案。

## Guard

- `.ai/ARCHITECTURE.md` §6 把「大陆可达性」列为硬约束。
- 本文件 + 决策文件里的观测矩阵，是重新引入 CDN 前必须复读的材料。
- **验证方法论（最容易再犯的一条）**：早先曾用 **Azure 香港**做观测点得到 300/300，
  据此误判为「本地上游运营商偶发抖动」，浪费了一轮排查。
  **境外观测点无法检测大陆封锁。** 判断大陆可达性必须用**大陆**观测点，且多点交叉。

## 相关影响

`zeroicey.me` 与 `gh.zeroicey.me` 解析到**同一对**被封锁 IP —— 用户主站在大陆同样
不可达。这比 teleport 本身影响更大，但不属于本仓库，需单独处理。
