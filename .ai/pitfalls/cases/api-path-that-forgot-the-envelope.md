# 只有打线上才会暴露的那个契约缺口

**症状**：`https://clip.hcyj.xyz/api/nope` 返回 **`text/plain` 的 404**，
而同主机上所有正常的 API 响应都是 JSON 封套。

**为什么本地测试没抓到**：本地那批测试断言了「未知 deep path 是 404」、
「保留字后缀被拒」、页面与 raw 的各种状态码，**唯独没有断言「未匹配的 `/api/*` 必须仍是 JSON」**。
那个断言我一直以为"显然成立"，所以从没写下来。

## 根因

路由用 NoRoute 兜底分发公共路径（第一个路径段是用户选的后缀，所以不能用 `/:suffix` 注册——
会和 `/api/...` 这类静态兄弟节点一起把 Gin 的基数树推进它处理最差的那种配置）。
于是 `/api/nope` 落到同一个分发器里，走到 `notFoundPlain` —— 那是给**页面**路径准备的
`text/plain` 404。

对一个打错端点的客户端来说，这不是"少了个字段"，而是**响应形状变了**：
它得为拼错 URL 单独写一套错误处理，而 `text/plain` 的 404 更像是反向代理发出的，
不像应用发出的。

## 修复

在公共路径分发器里，把 `/api` 子树先摘出去：

```go
if parts[0] == "api" {
    fail(c, http.StatusNotFound, "not_found", "未知的接口路径。")
    return
}
```

页面路径**保持** `text/plain`（那边是人手打的 URL，纯文本提示更合适），
raw 与页面路由的行为一个字节都没动。

## 守卫

`TestUnknownAPIPathAnswersInTheEnvelope`：对 `/api/nope`、`/api/clips`、
`/api/clips/ops1/extra` 三个形状断言 **Content-Type 是 application/json**
且响应体能解出封套（`ok:false` + 非空 `code`）。

注意这条同时断言了「页面路径**不**走这条规则」：本地的其他测试继续断言
`/a/b/c` 是 `text/plain`，两种形状各有人守。

## 教训

1. **「显然成立」的契约最容易被漏掉。** 我把 14 项契约逐条 grep 过测试引用，
   但这一条根本不在我的清单里 —— 因为它属于"我以为不需要写"的那一类。
   教训是：清点契约时，要把**每种响应形状**都当成独立条目，而不是只列业务规则。
2. **线上验证不是"再跑一遍同样的东西"。** 这次线上那一轮里 6 项契约检查有 5 项绿、
   1 项红，而红的这项在本地从未被断言过。只在本地跑，它会一直是绿的。
3. 顺带印证了拆分决策：这个缺口出现在 **clip** 自己仓库的验证脚本里，
   而它的修法（页面用 text/plain、API 用封套）也完全是 clip 自己的取舍 ——
   放在共用仓库里，这种"每个服务各自的响应形状"很容易被另一边的约定带偏。
